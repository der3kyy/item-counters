# ItemCounters

Счётчики для инструментов, оружия и брони: сломанные блоки, убийства мобов и игроков, полученный урон. Есть рейтинги, награды за достижения и поддержка PlaceholderAPI.

**Требования:** Minecraft 1.21.10, Paper/Purpur, Java 21. PlaceholderAPI необязателен.

## Что нового в 1.0.1

Исправлен баг с прочностью: ItemCounters мог заменять предмет во время обработки ванильного урона или использования. Из-за этого мечи и броня иногда не теряли прочность, даже если на самом предмете не было счётчика.

В 1.0.1 опасные замены предметов убраны или перенесены после ванильной обработки, поэтому обычный износ снова работает корректно.

## Установка и применение

Положите JAR плагина в папку `plugins/` и запустите сервер. Настройки появятся в `plugins/ItemCounters/config.yml`, переводы находятся в `plugins/ItemCounters/lang/`.

Выдайте счётчик командой `/counter give <игрок>`. В наковальне положите подходящий предмет **слева**, выданный счётчик **справа**, затем заберите результат. По умолчанию используется компас. Применение бесплатное. Обычный компас и копия названия не подходят. Расходуется один счётчик; повторное применение к тому же предмету запрещено.

## Что считается

| Предмет | Статистика |
| --- | --- |
| Кирки, лопаты, мотыги | Все сломанные блоки |
| Топоры | Все сломанные блоки, включая камень |
| Мечи, булавы, луки, арбалеты, трезубцы | Убийства мобов и игроков отдельно |
| Шлемы, нагрудники, поножи, ботинки | Полученный урон в сердцах: 1 ❤ = 2 HP |

Учитывается только предмет со счётчиком. Урон после уменьшений и поглощения делится между надетыми частями брони со счётчиками; в рейтинге игрока он учитывается один раз. Для стрел и трезубцев запоминается оружие выстрела. Смена предмета в руке не переносит убийство на другой предмет.

Отменённые действия не учитываются. В Creative подсчёт по умолчанию выключен. В Spectator он не работает. Элитры, ножницы и волчья броня не поддерживаются. Имя, зачарования и чужое описание предмета сохраняются. Счётчик передаётся вместе с предметом; защиты от потери при смерти нет.

## Команды и права

Аргументы в `<...>` обязательны, в `[...]` необязательны. Команды предметов работают с основной рукой выбранного онлайн-игрока. Если имя не указано, используется ваша рука. Из консоли имя обязательно.

| Команда | Действие |
| --- | --- |
| `/counter help` | Справка |
| `/counter give <игрок>` | Выдать один счётчик |
| `/counter apply [игрок]` | Добавить счётчик без наковальни |
| `/counter remove [игрок]` | Удалить счётчик с предмета |
| `/counter inspect [игрок]` | Посмотреть статистику предмета |
| `/counter set <характеристика> <число> [игрок]` | Задать значение |
| `/counter add <характеристика> <число> [игрок]` | Прибавить значение |
| `/counter subtract <характеристика> <число> [игрок]` | Вычесть значение |
| `/counter top <категория> <daily\|weekly\|alltime> [страница]` | Открыть рейтинг |
| `/counter reload` | Перечитать настройки и переводы |

Характеристики: `blocks`, `wood`, `mob_kills`, `player_kills`, `damage`. Выберите характеристику, подходящую предмету. `value` заменяет `blocks/wood/damage`; `total_kills` вычисляется автоматически. Для блоков и убийств используются целые числа, для урона можно указать дробное. Значения не опускаются ниже нуля. Административные изменения не увеличивают рейтинг игрока.

Права `itemcounters.use` (справка) и `itemcounters.top` (рейтинги) доступны всем по умолчанию. Права администратора: `itemcounters.admin.give`, `.apply`, `.remove`, `.inspect`, `.reload`, `.edit`. Сокращения начинаются с `itemcounters.admin`, право `.edit` разрешает set/add/subtract. Все права администратора по умолчанию у OP. `itemcounters.admin` объединяет их.

## Рейтинги

Категории: `pickaxe`, `shovel`, `hoe`, `axe`, `sword`, `mace`, `bow`, `crossbow`, `trident`, `armor`, `mixed`. Общие категории `blocks`, `wood`, `kills`, `damage` тоже доступны.

Периоды: `daily` (день), `weekly` (неделя), `alltime` (всё время). `mixed` показывает каждого игрока один раз по его лучшему числовому результату среди инструментов, без сложения разных счётчиков. Пример: `/counter top mixed alltime`.

Рейтинг принадлежит игроку: передача предмета не передаёт его место. Дневные и недельные результаты сменяются по часовому поясу сервера или выбранному в настройках.

## PlaceholderAPI: предмет в руке

Плейсхолдеры предмета читают основную руку игрока. Расширение встроено в плагин. Скачивать его через eCloud не нужно.

| Плейсхолдер | Результат |
| --- | --- |
| `%counter_has%` | Есть ли счётчик: true/false |
| `%counter_type%` | blocks, wood, weapon или armor |
| `%counter_value%` | Основное значение с форматированием |
| `%counter_raw_value%` | Основное значение без форматирования |
| `%counter_mob_kills%` | Убийства мобов |
| `%counter_player_kills%` | Убийства игроков |
| `%counter_total_kills%` | Общее число убийств |
| `%counter_damage%` | Урон в сердцах |
| `%counter_unit%` | Подпись значения с нужной формой слова |
| `%counter_id%` | Уникальный ID предмета |
| `%counter_block_word%`, `%counter_kill_word%` | Форма слова «блок» / «убийство» |
| `%counter_mob_word%`, `%counter_player_word%`, `%counter_heart_word%` | Форма слова «моб» / «игрок» / «сердце» |

## Плейсхолдеры топов

Топы работают через PlaceholderAPI и не зависят от предмета в руке. Формат: `%counter_top_<категория>_<период>_<место>_<поле>%`. Места начинаются с 1.

Пример: Alex занимает первое место общего топа с результатом 2 блока киркой. Язык плагина `ru_RU`, оформление стандартное. Ниже указаны буквальные ответы плейсхолдеров. Меняйте `mixed`, `alltime` и `1` на нужную категорию, период и место.

| Плейсхолдер | Что показывает | Пример ответа |
| --- | --- | --- |
| `%counter_top_mixed_alltime_1_name%` | Ник игрока | `Alex` |
| `%counter_top_mixed_alltime_1_value%` | Число с действием | `2 блока киркой` |
| `%counter_top_mixed_alltime_1_raw%` | Число без форматирования | `2` |
| `%counter_top_mixed_alltime_1_position%` | Место | `1` |
| `%counter_top_mixed_alltime_1_category%` | Категория результата | `pickaxe` |
| `%counter_top_mixed_alltime_1_action%` | Подпись действия | `блока киркой` |
| `%counter_top_mixed_alltime_1_line%` | Готовая строка с цветами | `&61. &eAlex &7— &62 блока киркой` |

На голограмме последняя строка выглядит как `1. Alex — 2 блока киркой` с цветами из языкового файла. Ник, место, число и действие зависят от статистики. Текст и цвета задаются в `leaderboard.row`, `leaderboard.value` и `units`.

Категории: `mixed`, `pickaxe`, `shovel`, `hoe`, `axe`, `sword`, `mace`, `bow`, `crossbow`, `trident`, `armor`; общие: `blocks`, `wood`, `kills`, `damage`. Периоды: `daily`, `weekly`, `alltime`.

Примеры: `%counter_top_mixed_alltime_1_line%`, `%counter_top_pickaxe_daily_1_value%`, `%counter_top_sword_weekly_1_name%`. Для голограммы используйте `%counter_top_mixed_alltime_1_line%`, затем такие же строки с местами 2, 3 и далее.

Короткая форма `%counter_top_1_value%` и другие поля берут категорию/период из `leaderboards.default-category/default-period`. Для отсутствующего места возвращается `leaderboards.empty-placeholder` (по умолчанию `—`). Плейсхолдеры предмета без счётчика возвращают `placeholderapi.empty-item` (по умолчанию `0`), а `%counter_has%` возвращает `false`.

## Настройки и оформление

| Раздел | Что меняется |
| --- | --- |
| `general.language` | ru_RU, en_US или свой файл языка |
| `anvil` | enabled, материал counter-material, блеск counter-glow, цена level-cost (от 0 до 39 уровней) |
| `counting.creative` | Подсчёт в Creative |
| `supported-items` | Включение blocks, wood, kills, damage |
| `entity-exclusions` | Исключённые сущности: types и регулярные выражения patterns |
| `number-format` | Разделители тысяч/дробей, damage-decimals |
| `leaderboards` | Часовой пояс, начало недели, категория/период по умолчанию, размеры топа/страницы, обновление и хранение старых периодов |
| `storage` | SQLite/MySQL, имя файла, flush-seconds, импорт legacy-import и параметры подключения MySQL |
| `milestones` | Награды за пороги на отдельных предметах |
| `placeholderapi` | enabled и ответ без предмета empty-item |

`counter-glow: false` по умолчанию; настройка влияет на вновь выданные счётчики. Блеск не добавляет зачарований. Числа округляются только для отображения.

В языковом файле редактируются `messages`, `usage`, `help`, `counter-item` (выдаваемый предмет), `item-lore`, `inspect`, `units`, `categories`, `periods`, `leaderboard` и `forms`. Цвета задаются кодами `&`; курсив по умолчанию выключен, `&o` включает его.

Переменные описания/просмотра: `{value}`, `{raw_value}`, `{mob_kills}`, `{player_kills}`, `{total_kills}`, `{damage}`, `{unit}`, `{type}`, `{id}`, `{block_word}`, `{kill_word}`, `{mob_word}`, `{player_word}`, `{heart_word}`. В просмотре также есть `{player}`.

`forms.rule` выбирает russian/english. Словари `block/kill/mob/player/heart` содержат `one/few/many/other`: «1 блок», «2 блока», «5 блоков»; дробные значения, включая 1.0, используют other. Шаблон `units.pickaxe: '{block_word} киркой'` подбирает форму автоматически. Для своего словаря можно использовать `{имя_word}` и `%counter_имя_word%`.

Шаблоны рейтинга используют следующие переменные: `header` принимает `{category}`, `{period}`, `{page}`; `row` принимает `{position}`, `{player}`, `{value}`; `value` принимает `{value}`, `{unit}`. Подсказки команд поддерживают `{usage}`, ответы используют переменные соответствующего действия.

После правок выполните `/counter reload`. Подключение хранилища, интервал сохранения, часовой пояс/начало недели, интервал обновления топа и регистрация PAPI требуют перезапуска. Настройки и собственные переводы сохраняются при обновлении файлов; ошибочный reload оставляет прежние настройки.

## Награды и хранение

Награды по умолчанию выключены. Пример: алмаз за 100 убийств на предмете.

```yaml
milestones:
  trigger-on-admin-change: false
  kills:
    '100':
      commands:
        - 'console:minecraft:give {player} diamond 1'
```

Категории наград: blocks, wood, kills, damage. Для дробного порога используйте `'100_5'` вместо 100.5. Каждый порог срабатывает один раз для предмета. `console:` запускает команду от консоли, `player:` выполняет её с правами игрока; слеш не нужен. Переменные: `{player}`, `{uuid}`, `{item}`, `{threshold}` и переменные предмета выше. `trigger-on-admin-change` разрешает награды при административном изменении значения.

По умолчанию статистика игроков хранится в SQLite (`counters.db`). Для MySQL задайте `storage.type: mysql` и подключение в `storage.mysql`, затем перезапустите сервер. Смена типа сама не переносит данные. `legacy-import` однократно импортирует старый JSON в пустую базу, сохраняя исходный файл и резервную копию. Перед обновлениями сохраняйте миры, данные игроков и базу вместе; аварийное завершение может потерять последние несохранённые действия.

Для интеграций с другими плагинами доступен Java API: чтение, добавление, изменение и удаление счётчиков. Изменения через API не увеличивают рейтинги.
